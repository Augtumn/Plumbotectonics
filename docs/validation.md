### 1.1 关于 lower 库的 6.4903

Table 4 的 **PDF 文本层**把 lower 库 `238U/204Pb` 读成 **6.1903**，与同一行其它
数值不自洽；**扫描图上实际印的是 `6.49030`**。本仓库使用图上真值 **6.4903**
作为校验目标，模型实测 6.4903，偏差 +0.00003。

误读原因是文本层为扫描 OCR，存在系统性的 `4` → `1` 混淆；同类未修正项见
§4.8。

### 1.2 标定说明

以及初始比值 `INIT_RATIOS = (9.0668, 9.9367, 28.6528)` 是**校准到
Table 4** 的数值，不是 Table 3 的印刷整数。Table 3 的印刷值（Pb：
`E_a2=80`、`F_a3=1.00`、`E_b1=40`、`E_b2=25`、`E_b3=25`、`F_c3=3.67`
等）保留在论文中作为量级参考。

## 2. Version I：与 Zartman & Doe (1981) Table IV 对比

> 目标值的原始出处截图见
> [`outputs/results/literature/`](../outputs/results/literature/)
> （Table II、Table IV 与 eq. 17–19）。

`scripts/run_version1.py` 把 11 个旋回 × 4 个储库 × 3 个比值（126 行）与
Table IV 逐项对比，输出 `outputs/results/version1_comparison.csv`：

| 指标 | 值 |
|---|---|
| 最大绝对偏差 | 0.005089（t = 1.6，mantle `207/204`） |
| 最大百分比误差 | **0.0349 %**（t = 3.6，mantle `207/204`） |
| RMSE | 0.002729 |

Table IV 只印到两位小数，0.005 即该表的精度极限。126 项中唯一越过这条线的是
t = 1.6 Ga 的 mantle `207/204`（模型 15.1551 / 表值 15.15，偏差 0.00509），
属于四舍五入的边界情形。

现今（t = 0）四个储库，模型 / Table IV：

| 储库 | 206/204 | 207/204 | 208/204 |
|---|---|---|---|
| 地幔 | 18.0782 / 18.08 | 15.4156 / 15.42 | 37.6804 / 37.68 |
| 造山带 | 18.8783 / 18.88 | 15.6261 / 15.63 | 38.8248 / 38.82 |
| 上地壳 | 19.3335 / 19.33 | 15.7273 / 15.73 | 39.0648 / 39.06 |
| 下地壳 | 17.2911 / 17.29 | 15.2991 / 15.30 | 38.5580 / 38.56 |

**结论**：Version I 在 Table IV 的印刷精度内逐项复现全部 126 个值
（最大偏差 0.00509，相对 0.035 %），与 Version IV 对 Table 4 的 0.028 %
处于同一量级。

### 2.1 曾经的 1.5 % 偏差：根因与修复

修正之前，Version I 与 Table IV 的最大偏差为 **0.5901（1.5303 %）**、
RMSE 0.1965，且文档曾把它归因为「论文正文与其结果表不自洽、无法通过修改
实现消除」。**该结论是错的**：论文是自洽的，偏差来自本仓库的实现。

根因在**造山带再分配**（[`theory.md`](theory.md) §2.5，论文 eq. 17–19）：

| 做法 | 首轮地幔分得造山带 Pb |
|---|---|
| 修正前：把分配比 `F_PB` 直接当作造山带含量的分数 | 2.8 % |
| 论文 eq. 17–19：按返回增量质量加权，除以 $s=\sum M_iF_i$ | $94.8\times0.028/5.1816$ = **51.3 %** |

首轮地幔贡献 100 个质量单位、只收回 94.8，而新上/下地壳各只拿 2.6，
因此地幔理应分到造山带的大头。按 2.8 % 分配会抽干地幔、喂饱地壳：

| 量（$10^{15}$ mol） | 修正前 模型 / Table II | 修正后 模型 / Table II |
|---|---|---|
| 地幔 204Pb | **11.46** / 19.5 | **19.48** / 19.5 |
| 上地壳 204Pb | **14.44** / 10.3 | **10.35** / 10.3 |
| 下地壳 204Pb | **12.10** / 8.2 | **8.17** / 8.2 |
| 地幔 238U | **104.4** / 174 | **173.5** / 174 |
| 上地壳 238U | **174.7** / 127 | **127.1** / 127 |
| 下地壳 238U | **69.9** / 48 | **48.5** / 48 |
| 地幔 232Th | **383.6** / 619 | **619.2** / 619 |
| 上地壳 232Th | **560.8** / 430 | **429.6** / 430 |
| 下地壳 232Th | **390.6** / 286 | **286.3** / 286 |

修正后 Table II 第三节 B 的 12 项全部落在 1 % 以内（最差 0.94 %，
下地壳 238U：48.45 / 48）。

> **两张表的时刻约定不同。** Table II 第三节 B 的绝对丰度对应
> **最后一次造山之后**的状态（质量 775.18 / 6.98 / 17.84 对 775.2 / 7.0 /
> 17.8）；Table IV 与第三节 A 的比值对应**造山之前**的状态
> （18.078 / 19.333 / 17.291 对 18.08 / 19.33 / 17.29）。本仓库
> `history` 记录的是后者，`run()` 返回的段储库是前者。

### 2.2 参数逐条核对

修正过程中逐条核对了论文的印刷参数，全部与实现一致，并且**足以复现两张表**：
$f_m$ 序列（1/8、1/16、1/32、1/64，其后 1/128）、上地壳侵蚀 3/10 与总地壳
面积侵蚀 1/10（合成 0.37）、每轮新建上/下地壳各 $2.6\times10^{24}$ g、
$E_m=4$、$E_u=E_l=1$、Pb/U/Th 分配比 (0.028, 0.754, 0.218) /
(0.024, 0.854, 0.122) / (0.020, 0.788, 0.192)、衰变方程形式，以及母体不随
衰变扣减的约定。

因此**不存在需要回避的「论文不一致」**：Table II 的参数 + eq. 17–19
即可同时复现 Table IV 与 Table II 第三节。曾被认为不可辨识的 eq. 14
分式（扫描件 OCR 为 `(~~/~~)`）也不再是缺口：正文「岩浆对地幔的质量比」
与 $E_m=4$ 的读法配合 eq. 17–19 就能给出正确结果。

## 4. 已知问题

### 4.1 `history['orogene']` 曾只含远端组分（Version IV，已修复）

`version4.py` 原先在

```python
oro_moles[h] = D_oro_h[0][2] + P_oro_h[0][1] + W_oro_h[0][2]
```

处求和，但该行位于 `P_oro_h[0][1]` 与 `W_oro_h[0][2]` 赋值之前，此时两者
仍为 0，因此 `history[...]['orogene']` 实际只等于远端组分 $D^{(2)}$，
缺少近端与楔形分量。

**影响**：仅影响 `history['orogene']`（绘图用）；储库结果与 Table 4
校验不受影响。

**状态**：已修复——把该行移到 `P_oro_h[0][1]` 赋值之后。

### 4.2 `constants.py` 与模型实现不同源

- `version1.py` 重复定义了 `L238`、`MASS0`、`F_PB` 等；
- `version4.py` 重复定义了 `CYCLES`、`A2`、`INIT_RATIOS` 等。

因此修改 `constants.py` **不会**影响模型。若要让常量集中管理，应改为从
`constants.py` 导入并删除重复定义（会牵动两个模块，建议单独提交）。

### 4.3 文档字符串位置（已修复）

`version4.py` 原先第 1 行是 `INIT_RATIOS = (...)`，位于模块文档字符串
之前，导致该字符串不是真正的 `__doc__`。已把 `INIT_RATIOS` 移到
docstring 与 `import math` 之后。

### 4.4 `pyproject.toml` 的 dev extra 含未使用的 `scipy`

`scipy` 在 `[project.optional-dependencies].dev` 中，但源码未导入；
可保留（便于后续拟合），也可移除。

### 4.5 `tests/test_version1.py` 的对照值曾标错

该测试原先把对照值写成 18.25 / 15.48 / 38.06 并注明来自 Table IV，但 Table IV
实际给出的是 **18.08 / 15.42 / 37.68**；18.25 / 15.48 / 38.06 是本实现的输出。
由于容差（0.5 / 0.3 / 0.5）对两套值都成立，这个错误不会导致测试失败。

**现状**：断言已改为 Table IV 的真值，并扩展到全部 **126 项**
（11 个旋回 × 4 个储库 × 3 个比值），容差收紧到 `0.006`；同时新增
Table II 第三节 B 的 12 项丰度校验与「分配比必须按质量加权」的回归断言，
上述两个错误都不会再被容差掩盖。

### 4.6 Table IV 中两处 orogene `208Pb/204Pb` 为扫描识别（OCR）错误

从 `papers/Zartman_Doe_1981_Plumbotectonics.pdf` 的文本层提取 Table IV 时，
orogene 列有两个值与物理趋势矛盾：

| t (Ga) | 提取值 | 采用值 | 依据 |
|---|---|---|---|
| 4.0 | 30.65 | **30.55** | 同行其余三个储库及表头初值都是 30.55 |
| 1.6 | 36.77 | **35.77** | 破坏单调性（34.95 → 36.77 → 36.56） |

`scripts/run_version1.py` 的 `TABLE_IV` 采用修正值；原始提取值记录在此便于核对。
其余各列的提取值均通过单调性检查。

**修正值已被模型独立证实**：正确实现给出 t = 4.0 orogene 30.550、t = 1.6
orogene 35.769，与采用值分别相差 0.000 与 0.001；而 36.77 无法由任何
参数组合得到。

### 4.7 环境依赖

`scripts/run_version4.py` 依赖 `pandas`；若环境中 `pandas` 与 `pytz`
版本不匹配，会抛 `ImportError: Can't determine version for pytz`。模型本身（`version4.py`）不依赖 pandas，可只用标准库调用。

### 4.8 Version IV 对照表中两个 sub 储库目标值取自 OCR 误读（**未修复**）

`outputs/results/literature/` 收录了两张对比表的文献原图。核对
`haines_zartman_1988_table_4_page2.png`（PLUMBO Table 4 第 2 页）后发现，
PLUMBO 报告的 PDF **文本层**是扫描 OCR，存在系统性的 `4` → `1` 混淆：

| 位置 | 图上实际值 | 文本层 OCR | 仓库当前取值 |
|---|---|---|---|
| lower `238U/204Pb` | `6.49030` | `6.19030` | 6.4903（已修正） |
| upper `232Th/204Pb` | `43.01600` | `13.01600` | 43.016（已修正） |
| **sub `207Pb/204Pb`** | **`15.44000`** | `15.11000` | **15.110（沿用误读值）** |
| **sub `232Th/204Pb`** | **`35.54200`** | `35.51200` | **35.512（沿用误读值）** |

`15.440` 与 `35.542` 另由 Zartman & Haines (1988) Table 1 的 Subcrustal
Lithosphere 列（207Pb/204Pb = 15.44）独立印证。

**影响**：§1 中「24 项全部满足 `|偏差| < 0.02`」这一结论对 sub 库
`207Pb/204Pb` 不成立——模型值 15.109975 相对图上真值 15.44000 的偏差是
**0.33**，而不是表中记录的 0.00003。（`35.512` → `35.542` 的修正会把该项
偏差从 +0.00993 变成 −0.0201，同样越过 0.02。）

**状态**：未修复。这不再是转录问题，而是 Version IV 的 sub 储库
（`207Pb/204Pb` 偏低 0.33，而同库的 206/204、208/204、238U/204Pb 都对得上）
需要单独定性，属另一项工作；在得出结论前不改动目标值，以免用调参掩盖。

> 教训：**文献值只能从图像核对，不能从扫描 PDF 的文本层转录。** Version I
> 的两张表是图像核对 + 模型独立复算，不受此影响。

## 5. 如何复现校验

```bash
uv sync --extra dev
uv run pytest -q
uv run python scripts/run_version4.py
```

或不安装、不依赖 pandas：

```python
import sys
sys.path.insert(0, "src")
from plumbotectonics.version4 import run, ratios

TARGETS = {
    "mantle": [18.473, 15.482, 37.729, 10.006, 2.7276, 27.29188],
    "upper":  [19.325, 15.727, 39.071, 11.077, 3.8833, 43.016],
    "lower":  [17.623, 15.351, 38.753, 6.4903, 6.0518, 39.278],
    "sub":    [18.318, 15.110, 38.101, 9.1292, 3.8932, 35.512],
}
KEYS = ["206/204", "207/204", "208/204", "238U/204Pb", "232Th/238U", "232Th/204Pb"]

res = run(dp=0.14)
for name, target in TARGETS.items():
    got = [ratios(res[name])[k] for k in KEYS]
    print(name, max(abs(g - t) for g, t in zip(got, target)))
```
